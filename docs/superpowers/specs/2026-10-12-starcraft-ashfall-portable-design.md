# StarCraft: Ashfall Windows 便携客户端设计规格

日期：2026-10-12
状态：用户已于 2026-10-12 批准书面规格，进入实现计划阶段。用户选择直接在独立项目目录工作，不创建额外 worktree。

## 1. 目标与范围

将 https://starcraft-shooter-2026.pages.dev/ 当前公开发布的游戏制作成 Windows x64 便携客户端。用户解压目录后双击 EXE，在独立窗口内离线游玩，不需要另开浏览器，也不在启动时从原站下载内容。

首版采用 Tauri 2 + Rust 宿主 + 现有 JavaScript/Three.js 内核，不将游戏代码转换为 Rust，不重写战斗或改变游戏平衡、解锁条件。保留原版界面、操作、作者署名和版权说明。首版供个人本地使用；公开分发前需另行核实代码和素材许可，本规格不授予分发权。

包含：窗口化和全屏、本地资源服务、完整资源清单、本地存档恢复及文件备份、诊断日志、便携目录和中文使用说明。

不包含：安装程序、WebView2 离线安装包、自动更新、线上账号或云同步、新启动器界面、原生 Bevy/wgpu 重写、改玩法或解除解锁条件。首版依赖目标电脑已有 WebView2，缺少时显示明确说明，不静默联网安装。

## 2. 已验证事实与证据边界

调研时公开页面使用 Vite 风格 ES Module 构建及 Three.js，资源映射包含 1,284 项，其中有 67 个 GLB、793 个 OGG、336 个 WebP。资源映射不等于完整依赖列表，构建脚本、CSS、动态模块、音频 Worker 等需递归收集。

已检查主程序存在 localStorage 本地排行榜键 sc-shooter-local-board 和 sc-shooter-season-board-v1。存档包装器的 authoritative 属性与本地胶囊版本有关，不足以证明依赖云存档。已发现反馈、遥测和开发测试请求；不能据此声称已穷尽所有联网行为。

本机已发现 Rust/Cargo 1.96.1、Windows MSVC 工具链、C++ 工具、Windows SDK 和 WebView2 154.0.4258.62。这只是环境发现，不是编译成功证明。

尚未下载全部资源、构建客户端或完成断网实测。完整可玩性、原版音效和录制功能兼容性必须通过后续验证，不承诺固定包体积、启动秒数或帧率。

## 3. 架构与职责边界

### 3.1 Tauri 桌面宿主

创建唯一主窗口，初始化 WebView2、窗口化/全屏切换及退出流程。采用稳定的应用标识和用户数据目录，并对该数据目录取得单实例锁；第二个实例显示“客户端已运行”后退出，避免两个实例互相覆盖存档。启动先校验必需资源并加载有效存档，再允许游戏主模块执行。窗口关闭后停止资源服务，确保没有残留后台服务进程。

仅在本项目目录内开发；不修改其他工作区项目，不替换 DSH GUI 或在其端口启动服务。

### 3.2 Rust 本地资源服务

监听 127.0.0.1 的可用端口，不监听 0.0.0.0；主窗口加载对应本地页面。外置游戏目录保留 /assets/... 根路径，由 Rust 明确映射文件路径，而不是假设 Tauri bundle.resources 或 localhost 插件自动映射外置目录。

仅提供指定游戏资源目录内的常规文件。支持 GET、HEAD、正确 MIME 和单段字节 Range（包括开放区间与后缀区间），合法分段请求返回 206，不可满足区间返回 416；不支持的多段 Range 拒绝而不产生错误内容。查询参数中的版本哈希不成为物理文件名。未知文件返回 404，不把 HTML 回退内容冒充 JS 或模型。

规范化和解码请求路径后校验目录边界；拒绝路径穿越、盘符、UNC、目录列表和指向资源目录外的链接/重解析点。验证 Host，拒绝不允许的方法及来源；不配置通配 CORS。宿主通过一次性引导地址建立本次会话的随机认证 Cookie（HttpOnly、SameSite=Strict），引导完成即作废入口；后续页面、模块、Worker 和媒体请求必须通过会话校验，不把随机端口本身当认证。引导令牌不写入日志或存档。资源根目录只读，HTTP 接口不提供通用文件写入或存档写入能力；此措施不宣称能够抵御同权限恶意本机进程。

网页导航仅允许本地游戏来源；外部链接不在有原生权限的游戏窗口中打开。IPC 权限限制为本窗口、必要命令和指定数据目录。启动时按实际监听端口为唯一游戏来源配置受限 IPC 授权并验证可调用性，不把所有 localhost 端口或远程来源开放为通用原生权限，也不把注入脚本视为绕过 Capability 的手段。若所选 Tauri 版本无法提供该精确授权，先报告阻断再调整设计。服务端口每次变化不应改变文件存档身份。

大文件采用异步流式读取或受控工作池，不在 UI 线程同步读入完整模型；资源并发有上限，单请求异常不拖垮其他加载。Windows 长路径前缀与不存在文件的规范化差异纳入测试。

### 3.3 资源获取与离线适配

资源获取是开发/打包步骤，不是客户端运行步骤。只获取公开可访问文件，不绕过访问控制。固定一次构建快照，递归收集入口、模块导入、动态依赖、Worker、CSS 引用、公开资源映射和必要配置，保留相对目录结构与作者归属。

清单记录来源 URL、本地相对路径、内容类型、文件大小及 SHA-256。只允许目标站点的已核实资源来源；限制下载并发、重试与超时。下载失败或拿到 HTML 错误页时明确报告，不能把缺失项标成成功。至少校验核心格式和模型依赖；发现构建入口已变化时重新解析快照，避免拼接不兼容版本。

原始发布产物与本地适配分开保存，适配步骤可重复执行。移除 Cloudflare 统计、在线反馈请求及不必要的 Service Worker 注册；明确关闭反馈发送并显示“本地版不提供在线反馈”，不返回虚假的成功提示。不隐藏游戏自身的真实错误。

检查并关闭 localhost 自动触发的开发工具入口和测试上报；确认 Worker 与音频资源仍能正常加载。运行期禁止公网 HTTP/HTTPS、WebSocket 等访问，使用 CSP 与 WebView 导航策略约束，并通过网络观测验证；CSP 需允许游戏必需的本地模块、媒体、Worker、blob/data 等已证实使用方式，不以关闭所有安全策略解决兼容性问题。

### 3.4 存档与恢复

游戏 localStorage 作为运行中的兼容存储；Rust 文件快照作为跨启动和跨程序目录的恢复依据。用户数据固定放在 Windows LocalAppData 下 StarCraftAshfallClient 目录，不写入 EXE 所在目录，不依赖当前工作目录或临时服务端口。

快照含客户端 schemaVersion、revision、保存时间和专用游戏来源的完整 localStorage 字符串键值。该来源不承载其他应用，因此首版保存其全部键，而非只筛选 sc-shooter-* 前缀；实现时核对游戏持久化调用，测试胶囊和 UUID 索引一起恢复。JSON 的数据字段保存字符串键值，不解释或修改游戏内部进度。快照文件和单次 IPC 的编码后上限均为 16 MiB，超限明确报告保存失败，不静默截断。

启动流程：Rust 读取并校验最新快照；损坏时尝试上一份有效备份，损坏文件隔离留存并不得参与下一次备份轮换，隔离失败则阻止保存并报告；在实际游戏来源通过文档初始化脚本同步完成存档回填，且仅在该启动阶段恢复一次。在任何游戏脚本执行前先清空该来源旧键，再恢复完整快照，防止已删除键复活；不采用游戏模块已执行后才异步回填的方式。首次无快照时保留有效的同应用现有存储或使用游戏默认值；不读取或迁移用户普通浏览器 Profile。主快照与备份均损坏时阻止自动启动，保留损坏文件供诊断，并要求用户明确选择恢复外部备份或新建存档，不静默重置进度。

监听 setItem、removeItem 和 clear 等已核实持久化路径，以完整快照同步删除与新增。异步 IPC 写入串行化并按 revision 拒绝旧快照覆盖新快照，revision 从已加载快照递增；短时间密集写入合并，在结算、设置变更等明确边界保存。Rust 宿主拦截关闭事件，先阻止窗口销毁，再等待最终快照落盘；前端响应或保存等待超过 5 秒进入原生错误对话框，不无限等待。保存失败默认取消退出，提供重试或明确确认不保存退出；不得因超时静默强退。确认退出后显式关闭窗口和服务。异常强杀仅承诺恢复最近已落盘状态。

存档使用同目录临时文件及 Windows 可用的安全替换流程，成功前不破坏当前有效文件，保留一份上次有效备份。原子替换、备份失败、磁盘满和权限不足需要可见错误提示；不把损坏快照自动写回覆盖有效备份。快照读取和 IPC 接收均有大小限制与 schema 校验，拒绝无法验证的数据。

首版恢复方式为用户退出客户端后备份或替换指定存档文件，再启动校验恢复；不增加复杂存档管理界面。说明文档明确存档路径、备份方式、失效恢复和卸载便携目录不会自动删除存档。文件存档恢复必须实际测试程序目录变化和服务端口变化。

### 3.5 日志与错误呈现

日志放在同一用户数据目录的 logs 子目录，限制大小和保留数量；不输出完整进度快照、原站反馈内容或凭据。

WebView2 缺失、资源清单不完整、服务启动失败、存档损坏、GPU 初始化失败分别显示可理解的诊断及日志位置。无法创建或使用 WebView 时通过 Windows 原生对话框呈现错误，不能只依靠加载失败的网页显示提示。发生不可恢复错误时不继续显示“启动成功”。

## 4. 数据流

启动：EXE定位只读游戏目录 → 校验必需资源 → 检查运行时 → 加载存档/备份 → 启动本地资源服务 → 创建受限窗口 → 恢复localStorage → 加载游戏模块。

游玩：原游戏读写状态 → 本地存储兼容层产生完整快照 → 受限IPC → Rust串行校验和落盘 → 成功确认。

退出：请求关闭 → 阻止继续产生新的游戏状态变更 → 获取最终快照 → 等待落盘/报告失败 → 关闭窗口和资源服务。

不从原站同步成绩、不将反馈排队到未来公网发送、不在客户端首次启动补下载资源。

## 5. 交付结构

便携目录包含主 EXE、game 资源目录、资源校验清单、中文使用说明及原作者署名/许可材料。开发仓库中的原始下载快照、适配脚本、Rust 宿主、测试和交付目录职责分离。媒体是否加入 Git 根据实际体积及许可决定；设计阶段只提交规格，不下载或提交第三方游戏素材。

资源路径根据 EXE/应用资源目录解析，不依赖启动工作目录；验证中文、空格路径与普通用户权限运行。首次使用不要求管理员权限。完整客户端仍依赖已安装 WebView2，说明明确其依赖；未来离线运行时打包需另立范围，不隐含在本版中。

## 6. 测试与交付验收

### 自动测试

- 资源路径：编码穿越、反斜杠、绝对路径、UNC、重解析点、404、查询参数、Host和方法限制。
- HTTP：GET/HEAD、MIME、普通文件、单段Range的206/416及正确长度，不支持的多段请求。
- 存档：schema与大小限制、胶囊/索引完整恢复、删除/clear、revision乱序、并发合并、损坏快照/备份、替换失败时有效文件保留。
- 离线适配：不改变原战斗代码；反馈和统计禁用、开发入口关闭、入口及动态依赖一致、重复执行结果一致。
- 便携包：清单与文件匹配、资源缺失可见错误、工作目录无关。

### 桌面实测

- 断开公网后，从未缓存的客户端 Profile 冷启动，进入游戏，完成至少一局开局、增援、升级、结算流程。
- 验证模型贴图、音效及流式配乐正常，键盘/鼠标输入、窗口化和全屏可用。
- 正常退出重启进度保留；更换程序目录与服务端口后存档不丢；损坏主快照能从有效备份恢复。
- 验证禁止公网请求，所有需要的资源从本地提供；没有后台残留进程。
- 验证普通用户、带中文和空格的目录；WebView2缺失与资源缺失时有明确提示。
- 若原站战报/录像功能在WebView中不可用，作为兼容性缺陷记录并评估，不宣称完整兼容。

记录实际启动耗时、内存、帧率和便携包大小，不设没有依据的固定阈值。自动测试或构建通过不能代替真实桌面和断网实测；未能执行的验收项目须明确标记未验收，不按完成交付。

## 7. 阶段与停止条件

第一阶段验证Tauri窗口、本地服务、代表性3D/音频和存档桥接；第二阶段获取一致的完整资源快照并适配离线；第三阶段集成真实游戏、自动测试、断网桌面验收和便携交付。

若完整资源缺失、许可限制获取、游戏动态逻辑无法在本地运行或WebView存在阻断问题，先报告证据和影响，再调整方案；不静默退化成联网快捷方式，不伪造成功验收。
